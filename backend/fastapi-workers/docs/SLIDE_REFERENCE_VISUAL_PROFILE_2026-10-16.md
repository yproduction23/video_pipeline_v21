## 폐기한 전략과 이유

- **편집 계획서 v1(`slide-edit-plan-v1`)**: "칠판 모션그래픽이 기본, 스톡·사진은 30% 이하"로 계획했다. 20번 Job에서
  칠판 97%·스톡 3%, 17~71씬(234초)이 하나의 칠판으로 이어졌다. 레퍼런스(스톡 67%, 회색 배경 최대 30초)와 정반대였고,
  원인은 10~34초 구간만 보고 전체 분포를 확인하지 않은 채 프롬프트에 가정을 넣은 것이었다. 폐기.
- **초록 칠판 배경 + 픽셀 잡음 질감**: 정지 이미지인데도 x264 인코딩이 3초 클립당 300초를 넘었고(71장면 생성 1시간+),
  레퍼런스의 문구 장면 배경은 초록 칠판이 아니라 어두운 회색이다. 폐기(어두운 회색 + 흐린 얼룩, 고주파 잡음 없음).

## 계획서 v2에 반영한 계약 (`slide_edit_plan.py`, `slide_edit_replan.py`)

- 배경 목표: 스톡 약 2/3(하한 55%), 어두운 회색 배경 약 1/4~1/3, 사진(Gemini, 유료) 8% 이하.
- 어두운 배경은 연속 30초(약 7장면)를 넘기지 않고, 배경 한 덩어리의 평균은 9초 이상(너무 잦은 전환 금지).
- 후편집은 장면의 45~80%(레퍼런스 56~74%), 스톡 장면의 후편집은 영상을 어둡게 눌러 얹는다.
- 위반은 계획서 생성 직후 최대 2회 부분 재계획으로 자동 보정하고, 남은 위반은 `plan.quality`에 기록해 화면에 표시한다.
- 계획된 스톡은 "정확히 같은 장면"이 아니라 주제·분위기에 어울리는 일반 영상이면 채택한다(완화된 선택 프롬프트).
  스톡을 끝내 못 찾으면 유료 사진이 아니라 회색 배경 + 원문 구절로 내려간다.

## 모션 시퀀스 (`slide_sequence.py`, 계획서 v3)

운영자 요구: 레퍼런스(부동산 영상 10~33초)는 회색 배경이 약 23초 동안 끊기지 않고 이어지며 요소가 문장 흐름에 맞춰
하나씩 등장·유지·교체된다("10억 원"+돈뭉치 → "현재·상위 11.8%" → 이어서 "과거·상위 7.9%" → 건물→화살표→돈뭉치 → 큰 숫자).

- **폐기한 방식**: 회색 배경 장면마다 독립 후편집 하나를 얹고 장면이 끝나면 사라지게 하는 방식(계획서 v1·v2). 장면 경계를
  넘는 연속성과 요소 누적·교체가 없어 레퍼런스의 "이어지는 애니메이션"이 되지 못했다.
- **계약**: 연속된 회색 배경 장면(run)마다 Claude가 요소 타임라인(종류·자리·등장 구절·동작)을 설계하고, 화면 글자는 요소마다
  기존 검증기(원문 일치·계산 검산·아이콘 화이트리스트)를 통과한 것만 쓴다. 설계가 비면 장면별 후편집으로 대체한다.
  등장 시각은 장면 내레이션 속 구절 위치 비율(문자 수 근사)로 정하고, 같은 자리에 새 요소가 나타나면 앞 요소는 교체되며
  center는 모든 자리와 겹친다. 하단 자막 영역(y>890)을 피하고 좌우 자리의 큰 숫자는 폭에 맞춰 줄인다.
- **렌더**: 시퀀스 시간축(t)에서 Pillow로 프레임을 직접 그려(올라오며 등장·튀어나옴·화살표 그리기·숫자 카운트업·막대 성장)
  ffmpeg 파이프로 인코딩하고, 장면마다 자기 시간 구간만 mp4로 만든다 → TTS·자막·장면 클립 계약은 그대로이고 화면만 이어진다.
- **한계**: 등장 시각은 단어 단위 TTS 타임스탬프가 아니라 문자 수 비례 근사다(±0.5초). 아이콘은 단순 도형이다.

## Kling을 기본 흐름에서 빼고 후작업으로 옮김 (2026-10-17)

**폐기한 전략**: 씬별 생성 중 스톡 미적중 장면을 Kling으로 바로 만드는 방식. 시험(작업 9024, 71장면)에서 요청 11건 중 2건만 성공했고 9건이 fal 대기열 180초 폴링에서 포기됐다. 직렬 호출이라 장면당 평균 3분 이상 걸려 전체 생성이 약 77분이었다. 포기한 요청은 fal에서 계속 진행·과금될 수 있다(장부에는 ₩0으로 남았으나 콘솔 대조가 필요하다).

**채택한 방식**: 기본 흐름은 Gemini 정지 이미지까지만 만들고(`slide_kling_enabled` 기본 꺼짐), 완성된 영상에서 단조로운 AI 배경 장면만 골라 Kling 클립으로 바꾸는 후작업(`kling_upgrade`)을 둔다.
- 경로: SlideProgressPanel 버튼(비용 확인창) → `POST /api/jobs/{id}/images/generate {sceneIndices, klingUpgrade}` → ImagesService → FastApiClient `kling_upgrade` → `SlidesWorker.generate(kling_upgrade=True)`.
- 이미 만든 Gemini 정지 이미지(`bg` 캐시)를 그대로 쓰므로 Gemini 비용이 다시 나가지 않는다. 정지 이미지가 없는 장면은 건너뛰고 사유를 검수 목록에 남긴다.
- 동시 요청은 3개로 제한하고 폴링 대기를 600초로 늘렸다(`SLIDE_KLING_POLL_TIMEOUT_SEC`). 다른 파이프라인의 기본 대기(180초)는 그대로다.
- Kling이 실패하면 정지 이미지를 유지하고 `kling_failure_reason`을 검수 사유로 남긴다.
- 후작업 뒤에는 영상 조립을 다시 해야 반영된다.

**미확인**: Kling 장당 비용(약 ₩490)은 장부 추정값이며 fal 콘솔 대조 전이다. 600초 대기로 성공률이 얼마나 오르는지는 실제 후작업 시험으로 확인해야 한다.

## 같은 스톡 두 번 쓰지 않기 (2026-10-17 운영자 결정)

- 클립 ID가 같은 경우만 막던 기존 방식에 더해, 클립 중간 프레임(1.2초)의 화면 서명(dHash 64비트, 거리 8 이하)이 이미 쓴 영상과 같으면 버리고 다른 후보를 최대 3번 다시 고른다. 다른 후보가 없으면 스톡 미적중(`near_duplicate_of_used_clip`)으로 처리해 Gemini 이미지로 내려간다.
- 캐시 재사용 장면과 이번에 다시 만들지 않는 장면의 영상도 같은 서명 목록에 먼저 등록한다.
- 운영자가 Gemini 대체 증가를 허용해 스톡 미적중 AI 대체 상한(`slide_stock_miss_ai_max`)을 12에서 20으로 올렸다(최대 ₩339×20 ≈ ₩6,780).
- **한계**: 서명은 화면의 밝기 구도만 비교한다. 같은 소재를 다른 각도로 찍은 영상은 같은 영상으로 보지 않는다. 어두운 영상끼리 우연히 가까워 불필요하게 버려질 수 있으며, 이 경우 Gemini 비용이 늘어난다.
